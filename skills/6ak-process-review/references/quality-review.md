# 业务语义复核

首次交付或业务变化后，核对本次模型、原文和派生的审阅稿。

## 语义复核

使用原文核对以下问题，并记录实际范围及发现。可使用独立 Agent 或人工复核；给复核者原稿与产物，避免用预设图形结构诱导判断。

| 维度 | 核对方法 |
| --- | --- |
| 断言支持度 | 检查重要角色、动作、输入、产出、系统与适用范围的证据是否真正支持其表达；逐字引用正确不等于解释正确。 |
| 关键内容覆盖 | 反向从原文寻找尚未进入节点、规则、关系或问题清单的重要条件、例外及限制，重点检查备注和跨章节信息。 |
| 关系正确性 | 核对方向、条件、并行、回退、数据交付与独立计划的区别；确认没有把段落顺序或版面邻接转成业务先后。 |
| 规则忠实度 | 核对触发条件、范围、例外和适用的数值参数，包括比较符、等号边界、单位及计算基准。检查不同口径是否各自保留。 |
| 不确定性 | 明示、推断、未知是否分别标识；推断理由能否成立；冲突双方是否保留；待确认项是否足以支持后续提问。 |
| 表达一致性 | 节点、后续流转、规则和疑点是否表达同一口径，整理分组与原文分组是否区分。|
| 反馈落点 | 检查本次引用的项目、对象和版本，局部改动是否影响了其他引用点，用户补充能否定位到用户的确认原话。|

输出无依据关键事实、关键规则改义、关键关系颠倒、推断冒充明示、掩盖实质冲突或遗漏影响执行的重要限制，均须修正后再交付。准确保留原稿中的缺失、冲突及其影响。

如果未发现业务内容，交付范围说明与问题记录，明确无法据此建立流程；不能编造最小业务节点。语义检查状态应反映实际审阅，不能从结构检查结果推导为通过。

来源正文变化后重查受影响的引用及语义解释。检查 `flow.md` 与 `model.json` 对应同一摘要。交付时分别说明结构检查、实际语义复核和业务未决事项。未复核的范围记录为未检查。行为验证见 [评估程序](../evals/procedure.md)。

## 工具回归

修改来源诊断、模型发布、审阅投影或批注存储后，运行包内测试。`PRICING_QA_DIR` 可指定可写的隔离父目录，测试自行创建并清理独立子目录。

```text
node --test "SKILL_ROOT/scripts/selftest.cjs" "SKILL_ROOT/scripts/compare-sources.test.cjs" "SKILL_ROOT/scripts/process-review-view.test.cjs" "SKILL_ROOT/scripts/grouped-review-draft.test.cjs" "SKILL_ROOT/scripts/review-workspace.test.cjs" "SKILL_ROOT/scripts/review-changes.test.cjs"
```

这些测试覆盖合成资料的增补和重排、依据失配、稳定对象编号、旧引用、批次重试、两轮处理以及多位置共享疑点。页面运行和真实读者验收另行记录；测试通过不代表任意原稿均能被正确理解。

草稿与工作区测试另覆盖项目目录隔离、迁移及旧引用、整批处理结果、同版摘要变化、提交重试、未知文件和链接保护。前端变化另用浏览器验证修改落点、审阅位置、新版通知和旧版输入保留。
