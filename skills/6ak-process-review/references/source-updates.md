# 接收更新后的原稿

适用于同一任务的原稿新增内容、删除、改写、重排或追加来源。以当前已发布模型作为基线，先识别哪些原始来源被更新；保留旧版本以及用户已经明确补充的来源。

## 变化诊断

按旧模型的来源编号显式指定新文件。文件名和传入顺序都不能代替来源身份；新增资料使用新的来源编号。工具只读输入，JSON 输出可保存在任务检查目录。

```text
node "SKILL_ROOT/scripts/compare-sources.cjs" "TASK/revisions/当前版/model.json" "原来源ID" "新版原稿.md" "新增来源ID" "新增资料.md"
```

输出区分 `unchanged`、`changed`、`added` 与 `unchecked`。未映射的来源没有检查，不等于未变化；旧用户补充无需重新造文件或替换。明确移除整个来源时，另外核对其陈述和依赖，不能把本次未传入视为删除。

对原有引文，诊断区分原位置匹配、唯一移动、多处匹配和不再存在，并列出受影响的陈述、前提依赖与业务对象。工具不会自动迁移引文、删除陈述或选择重复句子的落点。

## 修订模型

- 只要来源全文变动，就重新核对其覆盖和上下文。旧引文仍原位存在，也可能被新增的例外、范围或废止说明改变含义。
- 唯一移动仅提供位置候选；读取上下文后再更新行号。多处相同文字时核对具体段落，不取第一个匹配。
- 新内容可能引入新角色、条件、分支、独立片段或冲突。依内容归纳，不要求沿用原阶段数量或把新事实塞进旧结构。
- 同一业务对象的改名、移组和来源位置变化保留编号。拆分、合并或删除时，核对旧批注和关系影响；不把旧编号给不相干的新对象。
- 原文删去某句，不自动证明该制度失效；新版也不会仅因较新就推翻用户补充。需要选择权威口径而依据不足时，保留疑点。
- 以模型为业务主源修订陈述、证据、规则、关系、疑点和覆盖记录，重做实际受影响的语义检查，再生成同版文字稿。结构通过或引文匹配不代表解释正确。

## 旧批注与发布

从旧审阅版定位批注，再与当前对象比较。正文没有变化，但来源版本、依据或引用的业务陈述改变时，旧批注也需复核；页面的「本轮有修改」会标记依据或上下文更新。这个提示不自动判定意见已失效。

保留已处理结果和原版来源。待澄清意见可以继续处理；已落实或保留待确认的同一处理结果重发不会覆盖历史，不同的新意见用新批注记录。业务疑点是否解决仍由模型中的证据决定。
