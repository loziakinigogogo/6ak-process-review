一、对上一轮修改方案的调整

本轮只验证一件事：在保留现有正文审阅方式的前提下，增加只读流程图，是否能帮助用户理解结构，并准确找到需要核对的正文和依据。

- 保留：图与正文来自同一版 model.json；正文保留完整业务陈述及依据；图中保留分支、汇流、回路、不同关系类型和未决问题。
- 保留并复用：v0.1.3 已有的句子／选区批注、整步批注、批次交接、具体修改定位、版本保护与同版导出。这些不再另造一套。
- 撤回首轮版面重构：不把“图＋连续正文双主区域”、可拖动分隔条或新的正文编辑面板作为本轮目标。正文的组织与展开方式沿用正式版；图提供按需打开的预览。
- 移出首轮：图上多选、拆合节点、改字改线、手动条件编辑、疑点队列、新的 Agent 调用链、最终报告编辑器及新增导出格式。
- 后置：用户确认、确认进度图、撤销与内容变化后的待复核。第一增量经用户实际试用证明有价值后，再讨论第二增量。

“图与正文共享内容源”继续成立；“两者必须一直并排”和“审阅工具本轮兼任最终报告制作”不再成立。此前 report 可作为长文本和结构复杂度的参考，不作为当前模型的业务真值或本轮模板。

二、第一增量：用户实际经历的最短路径

1. 仍从现有正文开始阅读。在正文层增加一个“流程图”入口，进入同一页面中的宽幅只读预览；不在多层阅读抽屉中再叠一层图，也不默认占据正文空间。
2. 图展示当前正在阅读轮次的全部模型节点与关系。已知当前阅读对象时定位它，否则允许滚动、查找进入；不根据首组、排版顺序或入边数量宣布唯一业务起点。
3. 用户查看分支、汇流或回路。多出口节点提供图内局部“比较出口”：并列呈现每条关系的类型、完整条件原句、去向及相关疑点，不另开一套批注或编辑面板。
4. 点击节点定位已有步骤正文；点击关系定位该关系自己的流转说明、条件及依据，而非只打开终点步骤。目标藏在筛选或细节中时，临时切到可见范围并展开对应内容。
5. 用户在现有正文中读完整动作、查依据、批注。通过“返回流程图”恢复原焦点、图面位置与出口对照；退出预览则恢复原阅读位置。两种返回含义用明确文案区分，不积累新的业务路径层级。

首轮图入口只在正文层提供；现有阅读抽屉、搜索及批注输入不增加进入图的新组合。页面切换保留原正文及其未保存状态，不通过重载页面实现。正文的原筛选、滚动位置和已展开内容需要随返回恢复。

三、图的内容与可读性约束

- 第一增量不按确认状态隐藏对象；尚不存在用户确认接口。复杂图可以超出视口滚动，允许缩放和定位，不能把全部节点默认缩成难读的横条。
- 节点用模型已有标题标识。完整动作继续在正文阅读，不生成第二份可漂移的摘要。长标题允许换行。
- 分支对照保留完整条件原句；图上条件标签优先换行，长条件可关联到就近的完整对照。数值、比较符、单位和计算基准不得被省略成误导性的条件。不能仅靠悬停才能读完整。
- sequence、conditional、parallel、return、data、association 各自保留含义。数据交付与相关事项不包装为执行先后；回退能识别；多条同端点关系不因布局合并成一条。
- 多条入边只表示现有连接，不能自动补 AND／OR 等待规则。并列出口不自动意味着互斥或覆盖全部情况；资料未说明时仍显示未知或相应疑点。
- groups.kind 为 editorial 时明确为“整理分组”；不加阶段序号、组间箭头或强制串行布局来暗示业务先后。跨组连接、不连通部分均可找到。
- 推断标记与未知／冲突提示保留在相应对象附近，并能定位原句与 issue。同一 issue 多处提示只使用同一身份；不能根据“有来源”或“画成实线”宣布事实已经核实。
- 临时聚焦或突出当前节点只改变强调程度，不删除其余模型对象。若某个子视图限制了范围，需明确范围及返回完整图的入口，不能伪装为全流程。
- 键盘可进入图中对象和出口对照并返回正文；状态、关系区别不只依赖颜色。窄屏保证能读和定位，不承诺将复杂图塞满一个手机屏幕。

四、实现切口：只读、同轮、复用原定位

1. 数据入口
   现有 /api/review 返回的是审阅投影，不含完整模型和 groups.kind。不能从投影文字、正文序号或 destination 标签反推业务图。
   首选复用 GET /download/model.json?revision=N，其中 N 捕获自页面当前 review.revision。无需为了预览新增写接口或确认存储。读取后按任务与轮次缓存只读图数据，所有坐标与选择状态留在展示层。
   异步返回时再次核对任务、轮次和请求是否仍有效；过期结果不覆盖当前图。读取或布局失败时仍可使用原正文，并提供图的重试入口。

2. 版本衔接
   图预览打开期间纳入现有 hasReviewContext 判断，后台发现新版时提示用户，而非自动换正文后留下旧图。
   用户主动读取新版时，图和正文共同切换轮次；旧图缓存及待完成请求失效。可按稳定 ID 恢复仍存在的焦点；对象已删除时明确说明，不跳到相似标题对象。旧批注输入仍按正式版规则保留，不能改绑到新版。

3. 正文导航
   复用或小幅抽取 review.js 中 followItem、revealAnchor 的定位与细节展开能力，以及现有返回位置记录思路。
   不直接用 followStep 处理图上所有点击：它用于沿关系去终点阅读，不能替代关系本身的核对入口。
   节点、关系及条件陈述通过稳定对象身份关联现有展示位置。共享陈述允许有多个展示位置，批注仍对应原业务对象。

4. 修改文件范围
   assets/grouped-review/index.html：正文层入口、单一图预览容器、返回入口。
   assets/grouped-review/styles.css：预览空间、图形及出口对照、可读字号和窄屏表现。
   assets/grouped-review/review.js：显示切换、同轮加载、对象定位与返回、版本上下文保护。
   可独立增加 assets/grouped-review/graph-preview.js，承载纯展示投影、布局及渲染；如新增静态资源，仅在 scripts/grouped-review.cjs 的静态资源白名单登记。
   图布局不得通过 LLM 临时补线。确需布局依赖时随技能本地打包并记录许可，不依赖运行时外部 CDN。算法与依赖选择以复杂样本验证为准。
   references/grouped-review.md：说明预览用途、关系语义、跳转返回及实际支持范围。补充与上述行为对应的测试；不重写整理规则、批注协议和内容模型。

5. 兼容边界
   第一增量先支持 layout=process 的正式审阅页。旧自定义分组可能只有 claim／issue 展示位置，不能假造 node／relation 锚点；此类页面保持原功能，暂不开放图入口，后续支持需单独验证映射。
   不修改 model v1、已有 revisions／batches 或 pricing-ref:v1、pricing-review-batch:v1。没有节点的有效模型显示明确空状态，不推造流程。
   不迁移业务任务，不更新业务项目安装副本，不在这一轮提升发布版本。

五、验证顺序与停止条件

先记录技术正确性，再记录真实理解效果；两者分别交付，不能以测试通过代替用户试用结论。

技术验证：
- 在 .qa/ 中建立隔离合成任务，覆盖多个入口、多个出口、多重汇流、回路、跨组、不连通对象、重复端点的不同关系、长条件及未知／冲突。
- 检查图只反映现有节点和关系，未添加顺序或汇流规则；图的展开、点击、返回不会改业务文件或批次。
- 实际浏览器检查节点／关系／条件定位，筛选和折叠目标的可达性，返回位置、图视口与未保存批注保留，以及旧轮阅读期间发布新版、主动换版和过期请求。
- 检查过程视图旧任务、未启用图的自定义视图，以及原批注保存、差异定位和同版导出均可继续使用。
- 修改正式技能后运行 npm test。测试产物与截图存入 .qa/，注明实际覆盖范围；不据此宣称跨领域能力或业务规则正确。

理解效果验证：
- 使用复盘所述 31 节点、47 关系的实际材料只读副本，保留其模型轮次与来源。先核对副本实际数量；不可拿旧 HTML report 的 32 节点代替这份样本，也不修改业务原稿或任务历史。
- 不指导点击位置，请试用者找出一处分支的各出口、一次汇流及等待规则是否已知、一条回路、一处跨组联系，并定位对应正文与依据。
- 与原正文方式对照，记录误解、查找耗时、来回切换次数及反馈。样本和观察人数如实记录，不把单人练习当作普遍结论。
- 若产生把整理分组当先后、把数据关系当执行顺序、把汇流当全部等待、漏读分支条件等关键误解，或频繁往返反而增加负担，先修正或停止该交互，不通过新增编辑、确认与说明面板来补救。

第一增量交付物：可独立试用的只读图预览、兼容与技术检查记录、待用户试用的具体阅读任务。第一增量完成不自动意味着允许继续第二增量或发布技能。

六、第二增量保留的方向，不在首轮实现

第一增量经用户试用有价值后，再单独设计确认持久化与渐进显示。

- 确认是“已核对这一轮的当前表述”，对象可为节点或关系；节点确认不连带确认出入连接、条件，也不解决 issue，不替代 semantic／visual 复核。
- 可见范围为所有已确认对象、当前工作对象，以及与两者直接关联的一跳未确认对象。焦点和确认可同时成立；一跳不沿回路递归。当前显示的是局部审阅进度，需要说明未显示数量。
- 初始无确认及不连通部分从现有正文目录或查找进入，不猜唯一业务起点；数据与相关事项作为邻近对象时仍保留自身类型。
- 主动撤销只撤销所选对象并保留记录。新版使正文、关系、共享陈述或依据实际变化时，受影响的既有确认转为待复核，不抹掉历史；不采用“撤销所有下游”。
- 确认状态绑定任务、对象 ID、轮次及内容／依据指纹，存于独立的任务审阅状态；不写业务事实，不自动生成用户反馈来源，不进入 Agent 批次。文件、接口、旧任务无记录的默认值与迁移方案须在此阶段另行制定。

本计划不把第二增量视为已经获准开发的必选路线。
