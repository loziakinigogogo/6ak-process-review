## 一、对上一轮修改方案的调整

本轮只验证一件事：在保留现有正文审阅方式的前提下，增加只读流程图，是否能帮助用户理解结构，并准确找到需要核对的正文和依据。

* **保留**：图与正文来自同一版 `model.json`；正文保留完整业务陈述及依据；图中保留分支、汇流、回路、不同关系类型和未决问题。
* **保留并复用**：v0.1.3 已有的句子／选区批注、整步批注、批次交接、具体修改定位、版本保护与同版导出。这些不再另造一套。
* **撤回首轮版面重构**：不把“图＋连续正文双主区域”、可拖动分隔条或新的正文编辑面板作为本轮目标。正文的组织与展开方式沿用正式版；图提供按需打开的预览。
* **移出首轮**：图上多选、拆合节点、改字改线、手动条件编辑、疑点队列、新的 Agent 调用链、最终报告编辑器及新增导出格式。
* **后置**：用户确认、确认进度图、撤销与内容变化后的待复核。第一增量经用户实际试用证明有价值后，再讨论第二增量。

## 二、第一增量：用户实际经历的最短路径

1. 仍从现有正文开始阅读。在正文层增加一个“流程图”入口，进入同一页面中的宽幅只读预览；不在多层阅读抽屉中再叠一层图，也不默认占据正文空间。
2. 图展示当前正在阅读轮次的全部模型节点与关系。已知当前阅读对象时定位它，否则允许滚动、查找进入；不根据首组、排版顺序或入边数量宣布唯一业务起点。
3. 用户查看分支、汇流或回路。多出口节点提供图内局部“比较出口”：并列呈现每条关系的类型、完整条件原句、去向及相关疑点，不另开一套批注或编辑面板。
4. 点击节点定位已有步骤正文；点击关系定位该关系自己的流转说明、条件及依据，而非只打开终点步骤。目标藏在筛选或细节中时，临时切到可见范围并展开对应内容。
5. 用户在现有正文中读完整动作、查依据、批注。通过“返回流程图”恢复原焦点、图面位置与出口对照；退出预览则恢复原阅读位置。两种返回含义用明确文案区分，不积累新的业务路径层级。

## 三、图的内容与可读性约束

* 第一增量不按确认状态隐藏对象；尚不存在用户确认接口。复杂图可以超出视口滚动，允许缩放和定位，不能把全部节点默认缩成难读的横条。
* 节点用模型已有标题标识。完整动作继续在正文阅读，不生成第二份可漂移的摘要。长标题允许换行。
* 分支对照保留完整条件原句；图上条件标签优先换行，长条件可关联到就近的完整对照。数值、比较符、单位和计算基准不得被省略成误导性的条件。不能仅靠悬停才能读完整。
* `sequence`、`conditional`、`parallel`、`return`、`data`、`association` 各自保留含义。数据交付与相关事项不包装为执行先后；回退能识别；多条同端点关系不因布局合并成一条。
* 多条入边只表示现有连接，不能自动补 AND／OR 等待规则。并列出口不自动意味着互斥或覆盖全部情况；资料未说明时仍显示未知或相应疑点。
* `groups.kind` 为 editorial 时明确为“整理分组”；不加阶段序号、组间箭头或强制串行布局来暗示业务先后。跨组连接、不连通部分均可找到。
* 推断标记与未知／冲突提示保留在相应对象附近，并能定位原句与 issue。同一 issue 多处提示只使用同一身份；不能根据“有来源”或“画成实线”宣布事实已经核实。
* 临时聚焦或突出当前节点只改变强调程度，不删除其余模型对象。若某个子视图限制了范围，需明确范围及返回完整图的入口，不能伪装为全流程。
* 键盘可进入图中对象和出口对照并返回正文；状态、关系区别不只依赖颜色。窄屏保证能读和定位，不承诺将复杂图塞满一个手机屏幕。

## 四、实现切口：只读、同轮、复用原定位

### 1. 数据入口
现有 `/api/review` 返回的是审阅投影，不含完整模型和 `groups.kind`。不能从投影文字、正文序号或 destination 标签反推业务图。
首选复用 `GET /download/model.json?revision=N`，其中 N 捕获自页面当前 `review.revision`。无需为了预览新增写接口或确认存储。读取后按任务与轮次缓存只读图数据，所有坐标与选择状态留在展示层。
异步返回时再次核对任务、轮次和请求是否仍有效；过期结果不覆盖当前图。读取或布局失败时仍可使用原正文，并提供图的重试入口。

### 2. 版本衔接
图预览打开期间纳入现有 `hasReviewContext` 判断，后台发现新版时提示用户，而非自动换正文后留下旧图。
用户主动读取新版时，图和正文共同切换轮次；旧图缓存及待完成请求失效。可按稳定 ID 恢复仍存在的焦点；对象已删除时明确说明，不跳到相似标题对象。旧批注输入仍按正式版规则保留，不能改绑到新版。
