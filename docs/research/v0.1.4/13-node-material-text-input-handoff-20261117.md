## 2. 必须达到的录入体验

### 入口与输入

- 当前节点的“添加材料”直接进入文字输入，不先经过材料类型选择或多步向导。
- 在该节点工作区内就近呈现输入框并自动聚焦；用户无需到长正文底部寻找表单。具体位置可由主会话结合现有界面调整，不再堆叠多层 header。
- 唯一必填项是文字内容。支持手动输入与直接粘贴，保留有意义的换行，不自动改写原话。
- 不强制填写标题、选择栏目或进行事实／提醒／建议／问题分类；不要用自动生成标题等能力作为保存的前置条件。
- 输入区明确显示所属节点，沿用分组颜色、组内编号和节点名称。用户不需要再选一遍挂载目标。
- 仅空白的输入不能提交；失败原因应就近说明，已有文字不丢失。

录入示意，非固定像素稿：

```text
补充到「测算售价、供货价与配额」                 ×

┌──────────────────────────────────────┐
│ 粘贴资料，或写下需要补充、更正的内容……     │
│                                      │
└──────────────────────────────────────┘

                            [保存到此节点]
```

### 保存与反馈

- 保存成功后产生一条有稳定身份、归属和原话的节点材料；不依附于某条生成陈述。
- 明确反馈“已添加到「节点名称」”，同步材料列表；状态可显示“尚未用于当前结果”。该状态只描述使用情况，不代表内容真伪或意图判断。
- 用户可继续添加；收起输入区时保留未保存草稿。放弃输入须使用意思明确的操作，不能把收起当成丢弃。
- 保存后不强制把阅读位置滚到长列表末尾。可通过短暂高亮、就近回执或“查看这条材料”帮助确认结果，具体表现由主会话细化。
- 材料列表优先显示原话预览及必要的来源、时间、使用状态，支持修改与移出。没有标题时可直接使用原话开头作为展示预览，完整原话始终保留，不引入生成摘要的额外依赖。
- 标题、栏目和已有性质标记可以保留在旧记录或低频管理功能中；不再成为新增文字材料的必经步骤。

## 3. skill 与页面的职责边界

| 部分 | 本轮职责 |
| --- | --- |
| 页面 | 收取文字、保存原话、绑定节点、显示材料与使用状态、提供现有整理交接入口 |
| 现有交接 | 携带当前节点及材料的可追溯引用，交给现有 Agent 对话 |
| skill 当次任务 | 读取最新模型、原话材料和必要的上下游，按用户当次要求起草候选；需要澄清时在现有对话里处理 |
| 用户核对采用 | 继续沿用现有候选差异核对与采用机制，再同步节点结果和图结构 |

明确边界：

- 不增加网页聊天框、常驻对话 Agent、长期对话记忆系统或网页直连 LLM。
- 不把“后台自动理解整张图并持续陪聊”作为本轮能力。
- 不要求自动语义分类，也不承诺保存后会自动判断事实、建议或疑问。此前讨论中“Agent 后续自动区分”的表述不作为本轮产品需求。
- 新材料作为用户提供的原话进入现有任务上下文。不能因为用户省略分类，就默认为已核实的现行事实；也不能因为没有分类而将文字排除在整理交接之外。
- 持久保存的是节点资料及修改记录。一次 skill 任务可以从这些明确资料重新读取上下文，不要求另外建立聊天记忆。

“保存材料”和“根据材料重新整理”继续是独立动作：用户可以先连续补充多条文字，准备好后再发起现有交接。保存材料本身不调用 LLM、不生成候选、不改变当前业务结果。

## 4. 实现时必须处理的数据兼容

本支线只读核查发现，当前文字材料接口有 `fact / reminder / proposal / question` 的性质约束，且部分交接来源处理对 `fact` 有专门逻辑。因此本轮不能仅隐藏表单字段、继续偷偷填入某个有业务含义的默认分类。

主会话需要采用最小且明确的兼容表示，使“不要求用户分类的原话材料”能够保存、读取、修改并完整进入交接。具体字段及迁移方式由主会话结合现有材料存储决定，不在此固定新增 schema。

实施约束：

- 既有已分类材料保留原有性质、原话、版本、历史和采用记录，不批量改写旧内容。
- 新材料的“未输入分类”与“尚未用于当前结果”分开表达，不能把使用状态冒充语义分类。
- 核对节点材料上下文、交接引用、候选来源与验证逻辑，确保新原话不会被过滤遗漏，也不会自动取得“已核实事实”身份。
- 用户原话与节点身份使用稳定 ID。即使展示编号、标题或分组改变，材料和草稿的归属不变。
- 保持内容模型 v1、既有任务以及 `pricing-ref:v1`、`pricing-review-batch:v1` 兼容。需要调整材料扩展字段时，明确旧记录读取和迁移方式。
- 保留既有源文档片段入口，作为次要路径。本轮不新增文件上传、拖入文件或可视化文档选段功能；这些不是用户此次确认的实施范围。

## 5. 延续输入保护和导航要求

- 草稿按任务／工作区身份和稳定 node ID 隔离。输入文字、编辑对象和必要的版本基线，在切节点、关联跳转、返回、切模式及刷新后可恢复。
- A 的保存请求发出后切到 B，结果仍归 A，不能清空、替换或保存 B 的输入。请求归属绑定提交时的节点，不能在响应到达时重新取“当前节点”。
- 网络失败或响应丢失时保留原话；重试延续既有去重语义，不重复创建材料。
- 成功保存后切换、返回或刷新，不得重新打开已完成的表单，或误报“保存结果尚未确认”。保留对旧缓存完成标记与真实未确认请求的区分。
- 材料保存与候选采用状态继续分开。不能因为轻量输入就绕过候选核对，或把未保存草稿当作已保存材料送出。
- 外部模型更新导致节点删除或拆分时，保留输入并明确提示待处理，不按显示编号自动迁到别的节点。
