## 1. 本轮确定的布局

两种模式保留一级切换，可以采用不同布局。共用节点身份、内容数据和修改链路，不要求复用同一种面板形态。

| 模式 | 左侧／主要区域 | 右侧 | 主要任务 |
| --- | --- | --- | --- |
| 流程图 | 保留现有流程画布、分组导航和布局操作 | 保留现有节点详情抽屉 | 理解结构、分支和上下游 |
| 节点列表（当前 UI 可继续叫“节点内容”） | 窄的多节点目录，可按组浏览、查找和定位 | 常驻、占据大部分宽度的单节点工作区 | 查看节点结果、增补节点材料、发起 Agent 整理 |

节点模式的右侧是主工作区，不沿用窄抽屉的空间限制，也不在旁边再保留一套重复的节点预览抽屉。

左侧由多节点完整正文列表收敛为目录。仍能浏览全部节点，按组组织；可展示简短概括和必要状态，但不再在每个目录项下面展开整份正文、原文和编辑表单。

## 2. 单节点工作区的内容归属

**任何时刻，目录的当前节点、工作区标题、材料输入目标和整理操作目标，必须指向同一个节点。**

工作区包含三个职责清楚的部分：

1. **当前结果**：已采用的行动概括、完整正文、规则、后续关系、未知与冲突。Agent 整理后的内容只读。
2. **节点材料**：原文片段和用户原话都挂在节点上，可增补材料、修订用户原话或调整原文片段范围；保留来源、性质、版本与历史。不要把原文分别展开在每条生成陈述下面。
3. **根据材料重新整理**：以该节点的有效材料发起现有 Agent 交接，生成候选 `model.json`，经核对采用后同步结果、节点摘要和关联结构。

材料保存与结果采用是不同状态。材料有更新、结果尚未重新整理或采用时，应清楚提示；不能把草稿、提醒、建议或问题当作已生效业务事实。

完整结果与材料可以用分区、局部展开等方式组织；不要为了迁移布局再堆叠多层 header。新增材料后，应就近提供明确的当前节点整理入口，避免用户误用其他节点的操作。

本轮不增加直接修改生成正文的入口，不新增网页直连 LLM 的承诺。继承现有材料、引用、候选核对和采用能力。

## 3. 颜色与编号

- 继承当前流程图的语义：**颜色表示所属分组，数字表示组内节点序号**。不把组序号、组内序号和内部节点 ID 混用。
- 同一模型下，流程图卡片、目录项、工作区标题、关联目标链接和阅读历史中的同一节点使用相同标识。
- 关联目标的颜色来自目标节点所属组，不能继承当前节点的颜色。
- 编号按完整模型的组内顺序计算，不能因搜索、筛选或临时目录范围而重新从 1 编排。
- 持久身份、材料归属、草稿和导航历史仍绑定稳定的 node ID。模型结构变化造成展示序号变化时，不能把草稿迁给另一个同号节点。
- 标题始终可读；分组名称提供可访问的文字说明，目录组标题和必要的组外提示可显示组名。颜色不是唯一识别信息，也无需在每个引用旁重复长组名。

## 4. 关联跳转：在同一个工作区中导航

“后续与关系”主要属于工作区的当前结果。关系类型和条件保持只读；点击目标节点链接，即进入该节点的工作区。

以 A → B → C 为例：

1. A 的结果、材料及编辑入口都属于 A。
2. 点击 A 中的关联节点 B：先保留 A 的阅读和输入状态，再将工作区切换到 B；目录当前标识随之更新。
3. 点击 B 中的 C：重复相同规则，形成可返回的阅读历史。
4. 不创建“左边仍在编辑 A，右边临时预览 B”的双当前对象状态；也不增加一套覆盖主区的关联预览浮层。

目录单击、搜索结果和关联链接都应进入同一个节点工作区，避免形成多套导航规则。关系类型本身若没有独立操作，应呈现为标签或说明，避免形似按钮却无有用行为。

跨组查看时允许直接进入目标节点，工作区明确展示目标身份和所属组；不要悄悄把用户原来的分组筛选改成“完整流程”。若目标被目录筛选隐藏，在目录保留明确的“当前查看组外／筛选外节点”提示或当前项，并提供“在目录定位”。主动定位才调整相应分组或筛选，并保存可返回的原目录状态。

## 5. 返回与阅读位置

- 提供紧凑的“返回上一节点”和阅读路径。路径是用户的访问历史，不是对业务流转结构的修改。
- 从 C 返回 B，再返回 A，恢复对应节点原来的工作区滚动位置、展开区块和可恢复的输入焦点；不能每次回到顶部。
- 支持回到此次关联查看的起点；长路径可收敛显示，不能堆成多排标题挤占正文。
- 保存目录的筛选、分组展开及滚动位置。返回时恢复进入该节点之前的目录上下文。
- 同组、跨组、回路和重复访问同一节点都应可处理；不要把访问历史误实现为只允许每个节点出现一次的业务树。
- 以上返回指界面内的阅读返回；如同步浏览器 history，应避免与界面内返回产生双重跳转。

## 6. 未保存内容与异步操作

- 草稿按工作区／任务身份和稳定 node ID 隔离。切节点、关联跳转、返回、切换模式或刷新，均不得丢失已有未保存原话。
- 保留原话文本、标题、性质、所属栏目、编辑对象及必要的版本基线。正在编辑的原文片段范围等输入也需能回到正确节点继续；所用持久化方式由主会话结合现有能力实现。
- 目录可用简短标识提示“有未保存输入”，返回节点后可继续。自动保留草稿不等于自动保存为材料，更不等于采用到业务结果。
- A 的保存尚在请求中时进入 B：响应必须回写 A，不能清空或替换 B 的输入。网络中断、响应丢失后的重试延续现有去重语义。
- 无需在每次节点切换时弹出确认框。确实无法保留输入时，应如实提示并保护用户内容，不能静默丢弃。
- 外部 Agent 更新模型时，基线过期或节点被删除／拆分，应保留原输入并明确提示待处理；禁止按显示编号自动迁移草稿。

## 7. 两种模式之间的连续性

- 模式切换延续当前节点；节点材料和已采用结果仍来自同一份数据。
- 分别保存流程图视口／布局上下文，以及节点目录／工作区阅读上下文，不用一套滚动状态相互覆盖。
- 从节点工作区返回流程图，沿用现有节点定位规则；再回节点模式时能继续当前节点的阅读或输入。
- 流程图模式保留现有布局和操作方向，不因为节点模式改版而变成目录＋工作区。
- 窄屏可将目录改成按需打开的导航，但仍保持一个明确的当前节点和可靠的返回操作；不要把宽工作区压回不可用的窄抽屉。
