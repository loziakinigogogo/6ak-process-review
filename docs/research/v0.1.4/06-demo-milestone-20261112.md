### 建议试用顺序
1. 在“录入与审批”图中观察两种录入方式、降幅判断、审批和退回重算。
2. 点“校验降幅”，直接改图上名称、操作说明，以及两条出口的条件或去向，点击“保存节点”。
3. 切换节点或刷新，检查已保存内容与未提交输入各自恢复。
4. 把修改性质切为“先保存为待定建议”，核对图仍使用当前工作稿，建议单独保存。
5. 在“讨论”中提出问题，保存并复制真实引用，粘贴到 Agent 对话。
6. Agent 按技能固定命令读取请求、编辑候选模型、应用修改；原页面通过事件推送刷新。

## 三、保存与防覆盖机制

* `workbench/state.json` 中的 model 是有效工作草稿，保存会生成事务记录和版本摘要。
* `buffers/` 保存节点输入；待定建议与有效模型分开，未完整输入不会伪装成有效业务事实。
* 用户修订记录独立来源，保留原始来源与旧陈述；未知不自动清除，复核状态重新置为待复核。
* 用户与 Agent 共用版本检查。用户已提交新内容时，旧候选应用失败，必须重新核对。
* 页面正在输入时，远端内容更新保留输入；提交后继续键入的新内容也不会被旧保存回执清空。
* 服务响应和写入绑定任务身份，防止相同端口切换任务后旧页面误写。
* 撤销回退最近内容变化，保留后续布局和讨论；拖动节点只改变布局。
