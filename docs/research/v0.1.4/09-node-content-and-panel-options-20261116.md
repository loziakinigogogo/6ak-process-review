# 节点内容模型与右侧详情窗口方案

日期：2026-11-16。状态：设计研究，待选择与验证。依据 `docs/demo1_raw_file/` 和当前 `0.1.4-dev.1` 工作区；不是已实现功能或获准的业务改版。

建议先验证 **A：右侧完整阅读＋居中修订窗**。卡片承担扫读，右栏承担长内容阅读，修订临时进入独立区域，Agent 与布局操作回到选中对象附近。重点是分开职责，不继续给右栏增加页签和折叠层级。

## 1. 现状与问题

现有右栏默认阅读，点击「修订文案」才进入编辑，并非一直显示全部表单。它仍同时承载正文、连接、疑点、来源、Agent 入口、布局固定、待定编辑恢复和保存状态；已有草稿还可能把阅读直接切成编辑。

Agent 交接预览已经独立弹出，候选差异核对与确认应用在 Agent 对话及对应工具中完成。本轮不增加网页聊天、候选审批台或逐节点确认队列。

## 2. 通用节点内容模型

节点表示一个可独立理解的动作、事件或状态变化。主体可以是人、岗位、团队、系统或外部参与者；事件、等待和结果节点不强填执行人。

| 层次 | 内容 | 展示原则 |
| --- | --- | --- |
| 核心 | 做什么、谁、简短说明 | 标题最大最突出，一句短句；主体次要；说明用小号灰字，没有可靠增量时省略 |
| 身份 | 分组、组内数字、稳定节点 ID | 卡片只显示分组颜色与简单数字，不显示组名；稳定 ID 用于引用与数据关联 |
| 可选详情 | 范围、触发、输入、系统、完整操作、输出、完成判据、规则、补充、注意与风险 | 有依据才填；右栏完整呈现所有额外内容，不要求先固定成便签 |
| 证据与疑点 | 原文明示、整理推断、未知、缺失、歧义、冲突及来源 | 标在具体陈述／字段上，不能笼统把整个节点标为已确认 |
| 工作状态 | 未完成修订、待定建议、保存失败、版本变化、修改记录 | 与业务正文分开；保存、审阅完成均不自动证明业务事实 |

标题优先「动词＋对象」，状态节点可写「目标售价在前台生效」。灰字补充范围、方法或结果，不机械截取动作前两条，不重复标题。否定、关键条件和适用范围不能为缩短文案而丢失。

组内数字使用 `1、2、3`，不随拖拽位置变化，不替代内部 `node.id`，也不推导执行顺序；跨组同号用颜色、标题与上下文区分。颜色只表达分组，不兼任风险或编辑状态。

详情可以按「完整操作—条件与结果—补充与注意—待确认—依据」顺读，不必每类单开页签。关键未知明确显示；普通空类别可省空间，但“原文未说明”不能改成“不适用”。连接保留完整条件、类型和去向，不能把返回、数据交付、关联都叫“下一步”。

输出是产生的交付物或状态；完成判据是判断结果成立的标准，两者都不能无依据地生成额外必做动作。资料冲突保留双方原句与影响；访谈问题、风险评价、未来改进不能冒充现行步骤。

## 3. 原稿实例与边界

以下为显示归纳，不是新确认的业务事实。

| 主体 | 主标题 | 灰色短说明 | 进入详情的内容 |
| --- | --- | --- | --- |
| 各平台责任销售 | 测算目标销售／供货价格 | 结合底价、折扣范围和发货费用，形成目标价格 | 核算工具、费用口径、完整授权规则和渠道选择 |
| 平台系统 | 目标售价在前台生效 | 商品链接显示目标价格；提交成功不等同于生效 | 异步处理、适用范围、完成判据与例外 |
| 平台买手 | 核定托管供货申报价 | 对照申报价与竞品底线核价，通过或退回销售确认 | 核价结果、驳回路径、OA 底价映射疑点 |

依据：[SOP](../../demo1_raw_file/pricing_process_sop.md) 第 37、53、57、59 行；[核验清单](../../demo1_raw_file/platform_confirm_checklist.md) 第 47、62、73、78 行。

核验清单第 73 行尤其重要：前台显示目标价是生效判据，但不能据此新增「销售逐链接人工检查」步骤；供货基础价按平台核价结果表达。第 22 行说明许多工具路径仅为预填，不能直接当成已核实使用。第 41 行记录 Baijing 欧盟／非欧盟标签冲突，应保留双方，不能凭字段名裁决。本轮未独立核对原稿链接的外部源码或平台资料。

## 4. 三套摆放方案

三者共享节点模型与右侧完整阅读，区别在于修订任务放在哪里。全局历史、来源、导出保持原入口；Agent 预设和布局固定操作移到明确指向当前对象的工具条。

| 位置／行为 | A：居中修订窗 | B：底部修订台 | C：独立修订视图 |
| --- | --- | --- | --- |
| 流程图 | 中央，阅读时完整保留 | 左上方，修订时高度减少 | 默认宽画布 |
| 右侧详情 | 常驻阅读，可收起 | 常驻阅读，可收起 | 按需展开阅读 |
| 文案修订 | 点击后打开宽窗 | 停靠画布下方，右栏保持全高阅读 | 工作区切为宽文稿 |
| 保存、还原、待定建议 | 修订窗内 | 底台内 | 修订视图内 |
| 主要收益 | 职责清楚，迁移较少 | 可同时看图改字 | 大画布与长文空间充足 |
| 主要代价 | 编辑时不能自由操作图 | 占图高度，阅读／编辑对象可能不同 | 图与编辑切换成本最高 |
| 适合方向 | 先读流程、偶尔订正文案 | 高频对照上下游修订 | 集中长文修订 |

**推荐先验证 A**，基于当前网页主要承担文案订正、结构调整交 Agent 的边界；编辑频率仍需实际使用验证，不把这一假设当成既定用户习惯。若频繁需要边看图边改，再考虑 B；若以集中处理长文为主，考虑 C。首轮选一个，不同时提供三套修订入口。

A 的修订窗保留标题、已有陈述和**既有条件文字**编辑。增删节点、拆分、换分组、改连接去向继续交给 Agent。右栏保持已保存工作稿阅读；有草稿时只显示恢复入口，不自动接管正文。关闭窗口保留输入，与「还原输入」区分；保存为工作稿和保存待定建议也要区分。

沿用原节点草稿、版本校验和失败恢复；保留切节点输入、选文／对象引用、五类预设、内容撤销、历史与导出。修订窗转交 Agent 时先保留上下文，再用原预览替换，避免叠窗；未保存输入仍由用户主动选择附上。窄屏修订变整屏，返回恢复选择、视口和阅读位置。

## 5. Sticky note 的限定用途

默认没有便签；用户主动固定少量规则、疑点或来源摘录，用于跨节点对照。放在画布边缘预留区，不遮主线；标明来源节点、内容类别和回跳入口。

便签引用同一 claim／issue，不建立第二份可编辑正文，不承载聊天或待定建议列表。原文改变时同步或提示已更新；快照须标旧版，源对象删除须提示失效。关闭只取消固定，不删除内容或解决问题。所有内容仍可在右栏读到，不能自动把未知项铺成便签墙。

## 6. 兼容与验证范围

这是展示模型，不是内容模型 v2。保留 v1 七字段 `role/system/trigger/input/actions/output/rules`、稳定身份和现有任务目录；兼容 `pricing-ref:v1`、`pricing-review-batch:v1` 及工作台引用。现有校验拒绝额外字段，不能直接向 `nodes/fields` 加 `summary/displayNo`。

摘要可从现有 claims 派生；若持久编辑，须另定义版本化展示元数据、`nodeId/claimIds` 关联与失效重算机制。旧任务没有元数据仍能读；原陈述修改后摘要不能漂移，短卡也不能覆盖完整操作与证据。

本轮完成原稿与源码静态研究；可点击示意使用隔离的合成内容，只比较布局，不接生产数据或保存接口。未修改生产代码、技能或版本，未执行 `npm test`。

合成示意在 1024、736、390、320px 宽度执行了 116 项浏览器检查，全部通过且无页面脚本异常；覆盖三方案切换、横向溢出、节点详情绑定、返回与切节点保留输入、B 的阅读／编辑目标独立、固定对照与 Agent 预设入口。检查并修正了 B 的箭头命中区域遮挡节点点击，并查看桌面及窄屏截图。320px 轮次出现一次 Lucide CDN DNS 失败，文本标签与上述交互仍可用；图标完整加载未在该轮证实。结果、脚本及截图保存于 [本轮 QA 目录](../../../.qa/right-panel-research-20261116/preview-check-results.json)。这些检查只覆盖示意，不代表实际工作台功能已经实现或通过真实用户可用性验证，也不代表跨领域能力已验证。

后续选定方向，再用隔离任务检查长文、多出口、未知／冲突、草稿切换、版本变化和窄屏；跨领域能力按技能评估规程另行验证。
