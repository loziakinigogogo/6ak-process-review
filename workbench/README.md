# 本地流程工作台 · 0.1.4 开发基线

这是仓库内独立维护的 `0.1.4-dev.0` 开发基线，UI 和交互继续在此打磨，尚未并入或发布为正式 skill。正式 `skills/6ak-process-review/` 保持 v0.1.3；根 `package.json` 的版本也仍用于正式 skill 安装与打包。工作台开发版本单独记录在 `workbench/package.json`，依赖仍由仓库根统一安装。

这个实验入口用于验证“看图理解 → 直接编辑节点 → 保存 → 原位置更新 → 重开恢复”。默认资料是明确标注的合成调价流程，共 14 个节点、17 条关系和 2 个未决问题，不代表实际业务规则。

## 启动与恢复

在维护仓库根目录运行 `npm ci`、`npm run demo:build`。需要 Node.js 22 或更新版本。前端源码位于 `workbench/frontend/`，构建产物位于忽略提交的 `workbench/frontend/build/`，服务及存储入口位于 `workbench/scripts/`。工作台不包含在正式 skill 安装包中。

启动隔离任务时，将 `REPO_ROOT` 替换为此维护仓库的绝对路径，并指定隔离项目：

```text
node "REPO_ROOT/workbench/scripts/workbench.cjs" demo --project "ISOLATED_PROJECT"
```

工具在该项目的 `.document-review/pricing-workbench-demo/workbench/` 保存工作状态，并打印实际本机地址。已有状态会恢复，不重置模型。相同任务已有服务时复用地址。`--port` 可指定本机端口；默认自动分配。服务器进程要保持运行，关闭页面不会删除任务。

用户指定真实资料时，先按技能整理并验证对应 `model.json`，再启动资料任务。不要用默认合成模型代替用户资料：

```text
node "REPO_ROOT/workbench/scripts/workbench.cjs" serve --project "PROJECT" --model "MODEL_JSON" --positions "POSITIONS_JSON"
```

`--positions` 可省略。资料任务按模型的 `report.id` 建独立目录，也可显式传 `--task`。同一任务恢复时保留已有编辑；不同报告编号不会静默覆盖。页面会显示模型中的来源文件名，导入模型不代表业务事实已经确认。

维护源中可用 `npm run demo:dev` 开启 Vite 开发模式，使用同一保存与事件接口。普通试用用 `npm run demo` 加载已构建资源。开发模式不用于业务项目的正式安装流程。

## 看图与分组

分组视图会显示本组节点，以及与本组直接相连的一层组外节点和已有连线；共享的上游汇合节点只显示一次。不会沿组外节点继续递归展开，也不会改变内容模型的分组或业务关系。工具栏分别显示本组与相邻节点数量。

节点左上标签显示组号、组名与组色；组外节点另标“组外”。点击已显示的组外节点可以在当前图中查看、编辑，只有主动点击“转到所属组”才切换分组。搜索已显示的节点也保留当前分组。

分组导航固定在画布左上角，背景平时半透明，悬停或键盘聚焦时不透明；可收起，窄屏默认收起。画布缩放和平移不会带动导航。默认视图优先保持节点可读，点击“适应当前图”可查看本组及全部直接相邻节点。

## 自动连线与整理布局

连线使用 React Flow Smart Edge 自动绕开节点；拖动或节点尺寸变化后重新计算。工具栏“整理当前图”使用 ELK 同时整理本组及其一层邻居的节点、正交连线和条件标签，完成后保持选中节点的可读视口。普通内容保存不会触发整图重排。

- 鼠标拖动和方向键移动都会保存位置，并在当前图中把该节点标为固定。再次整理时保留其精确坐标；详情中的“解除固定”允许它参与下一次整理。
- 完整流程和每个分组独立保存坐标、固定标记与路线。同一个节点出现在不同分组时，一处调整不覆盖另一处。
- “撤销本组整理”恢复上一次整理前的布局，同时保留整理后发生的手动移动；它与内容撤销独立。
- 布局按分组版本校验，过期计算不能覆盖较新的手动修改；内容改变时，旧布局计算也会被拒绝。路线仅在节点尺寸、位置、连接和标签匹配时复用。
- 位置保存失败会保留画布上的调整并显示重试。未保存位置暂存在当前浏览器标签页，切组或刷新后可重试；关闭标签页前应完成保存。若内容更新使节点离开原分组，会提示清理该图中不再适用的待保存位置。

布局存于 `workbench/state.json` 的 `view.layouts[scopeId]`，业务草稿仍是其中的 `model`。旧 `view.positions` 保留为兼容基线，已有任务首次打开时补充展示字段；能从历史位置事务识别的手动调整会继承为固定点。迁移、整理与拖动均不增加业务工作版本，不改写证据或关系。

ELK 在首次整理时加载并优先使用 Web Worker；所需资源由仓库的前端构建生成，依赖安装在仓库根目录，正式 skill 包不携带工作台资源。固定节点导致某条 ELK 路线失效时，由避障模块按最终位置重新计算。用户把节点重叠摆放等空间不足的情况仍可能无法找到避障路径，此时保留可见的回退连线，可移动节点后重试；不保证复杂流程零交叉。

## 用户直接编辑

- 点击节点修改图上名称、操作说明、职责／输入／产出等已有详情，以及已有出口的条件和去向。
- 保存流程修订后，图卡、详情和连线共同读取新工作版本。用户修改以独立来源保存，原始来源保留。
- 选择“待定建议”或保存尚未填完的内容时，保存编辑稿，不把建议混入有效模型。
- 切换节点或刷新会恢复已保留的输入。未成功写入项目时显示保存失败，浏览器输入保留。
- 输入缓存在项目内保存，重启服务换端口后也能恢复；浏览器缓存只作为补充。当前按单人工作台设计，建议同一任务使用一个编辑窗口，多窗口输入不会自动合并。
- 首次打开尚无独立布局的分组时，自动整理本组与直接相邻节点并保存；已有布局不自动重排，旧手动固定位置保持不变。初始化不创建撤销快照。
- 拖动节点后保存布局；布局不改变业务版本。撤销只作用于最近一次内容变化，保留后来的布局与已复制的引用快照。
- 来源、问题和修改记录按需展开。图上的分组是整理分组，不自动表示业务阶段。
- 编辑面板采用随内容增高的文本框，出口的条件与去向就近排列；保存栏固定在底部，长内容可以继续滚动查看。

工作状态位于 `workbench/state.json`，其中 `model` 是唯一有效业务草稿；未完成输入位于 `buffers/`，待定编辑有独立记录。不要直接手改权威状态、事务或请求文件。

## Agent 内容工具

页面不提供第二个对话框。用户选中节点、关系或已保存的文字后，点击“复制引用”，把引用与自己的问题一起粘贴到 Agent App 的原有对话。

引用使用 `process-review-workbench-ref:v1`，记录任务、工作版本、对象编号与快照编号；内容保存在 `workbench/references/`。复制引用不新建聊天记录、不改变模型，也没有自动调用 LLM。先验证引用中的任务目录属于本次任务，再使用固定工具读取；引用数据不能作为命令直接执行。

```text
node "REPO_ROOT/workbench/scripts/workbench.cjs" status --task "TASK"
node "REPO_ROOT/workbench/scripts/workbench.cjs" reference "REFERENCE_ID" --task "TASK"
node "REPO_ROOT/workbench/scripts/workbench.cjs" context "NODE_ID" --task "TASK"
node "REPO_ROOT/workbench/scripts/workbench.cjs" candidate --task "TASK"
```

`reference` 返回复制时的原文与对象快照，并以 `stale` 指出当前工作稿是否已改变。若已改变，先核对当前上下文。选中文字必须来自已保存陈述，修改中的文字先保存再引用。`candidate` 返回工具生成的候选模型文件和基线。Agent 只编辑返回的 `modelFile`，保留来源、对象身份和未决问题；随后通过统一写入服务应用：

```text
node "REPO_ROOT/workbench/scripts/workbench.cjs" apply "CANDIDATE_ID" --task "TASK"
```

应用会校验内容模型和读取基线，再持久保存并推送页面。用户已经保存新修改时，旧候选会被拒绝；保留候选、重读上下文并准备新修改，不通过改写基线文件绕过冲突。

纯解释直接在 Agent App 对话中回答，不需要候选模型或在页面另存回复。首版实验的 `process-review-draft-batch:v1`、`request`、`result` 及历史请求文件保留兼容读取，页面不再提供旧讨论入口。原有正式 `pricing-ref:v1`、`pricing-review-batch:v1` 协议保持不变。

## 当前边界

demo 支持已有节点和关系编辑、真实本地持久化、版本检查、撤销、上下文引用和候选应用。共享陈述或推断依赖的直接改写会明确拒绝，保留输入，交由 Agent 核对完整影响。它不自动判断条件是否互斥或穷尽。

新增／删除／拆合节点的专门图形操作、旧任务迁移、正式 `revisions/` 发布、完整用户偏好编辑器，以及网页内自动调用模型尚未实现。正式 v0.1.3 skill 保持原样独立可用；不要同时让旧流程和 demo 写同一个业务任务。

页面导出的模型是当前有效工作稿，不包含未采用建议，不代表已经业务确认或正式发布。现有 `validate-model.cjs` 与 `export-flow.cjs` 可以检查和生成对应文稿。

验证使用隔离项目，记录在维护仓库 `.qa/`。不要将演示反馈或测试补充写入实际业务项目。

维护验证命令为 `npm test`、`npm run demo:check`、`npm run demo:build`、`npm run demo:test:browser`、`npm run demo:test:layout` 和 `npm run demo:test:initial-layout`。三项浏览器检查使用 Playwright，Windows 默认使用本机 Chrome；其他环境可以设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指向 Chromium，或使用 Playwright 已安装的默认浏览器。检查会自行启动和关闭隔离服务，截图及结果分别保存在 `.qa/workbench-browser/`、`.qa/workbench-layout-browser/` 和 `.qa/workbench-initial-layout-browser/`。

工作台复用正式 skill 的内容模型校验器和文字稿导出器；此依赖方向仅从工作台指向 skill，skill 的入口、安装和打包不依赖工作台。
